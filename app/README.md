# mmbox operator console

An optional application for the human who oversees the agents: configuration of the services, table of active boxes, messages (local logs, unread boxes, the services' collectors), sending a message or a broadcast, questions asked by the sessions and their answers, handling (execute, ask, ignore) per workstation or per box, settings and alerts. The details are in the [repository README](../README.md#operator-console).

```sh
python3 app/mmbox_console.py --open            # serves on http://127.0.0.1:8765/#token=…, shown at once in its window
python3 app/mmbox_console.py --browser         # no window of its own: the icon and --open use the default browser
python3 app/mmbox_console.py --whoami          # the operator id to give to MMBOX_OPERATORS
python3 app/mmbox_console.py --port 8800 --days 30 --refresh 5 --client ~/.local/share/mmbox/src/client/mmbox.py
python3 app/mmbox_console.py --no-tray         # without an icon in the notification area or a system notification
```

- Python 3.10+ standard library and `cryptography` (already required by the client). No build step, no web dependency.
- The operator key is in `~/.config/mmbox-console/` (`MMBOX_CONSOLE_HOME`): it is not a box, it is never paired.
- Actions go through `mmbox.py` itself (`send`, `chan post`, `server …`, `collector …`, `tune`), with its rules.
- Listens on 127.0.0.1 only; each API call carries the URL's token, and the `Host` header is checked.
- A message's state: `queued`, `sent`, `unread`, `taken` while it may still wait (the purge keeps them); `read` (a box took it), `consumed` (a message no log nor collector saw taken: the console asks its sender's service, `/v1/status`, which says it no longer holds it; asked once consumed, again every 2 min otherwise, 24 senders × recipients per refresh), `left in a closed box` (it waits in a box that closed before reading it: the relay forwards real messages to the machine box, the tool's own stay there), `dropped` (its sender gave up: the log says `dropped`, or it is no longer in its sender's outbox).
- **Project boxes**: a project box (role `project`, client/PROTOCOL.md "Project boxes") is the first entry of its project's folder under its machine, with its own icon; the explorer's *Project boxes* group lists every one whatever its machine (selecting it shows their messages), and the list's *Show* filter has *Project boxes*. A message the listener passed on to a project's box, or a session gave back, shows where it went.
- **Butler tab**: the computer's butler (client/BUTLER.md), run with the console unless Settings say otherwise (one per computer): its state, a chat with it, a form to start a session (folder, agent and model from its inventory, title, first task) and the sessions it started (state, tmux name, the end of a failed one's pane), the agents and models of this computer (probed every 6 h; *Refresh agents and models*, also in this computer's menu), and its whole live output (each step of its daemon, each event of each agent turn: thinking, tool calls, answers), filtered and pausable.
- **Your account (onboarding)**: while this console has no account, it opens on a window that makes it (a root key in the keyring, a recovery file sealed with a passphrase your password manager can make and keep) or joins it (approved from a device of the account with a code); app/install.py opens the console on it, or asks the account to pin on a computer without a display. client/ACCOUNTS.md.
- **The operator key**: the console's key pair is kept in the system's keyring (Secret Service on Linux desktops: GNOME Keyring, KWallet) or with DPAPI (Windows), else in a file only this user reads (a server without a keyring); a plain `identity.json` moves there at the next start. When its keyring does not answer (locked), the console stops rather than make a new key. `--has-key` says where it is; `--export-key FILE` seals it with a passphrase for another computer of the same operator, `--import-key FILE` takes it there.
- **In the applications menu**: `python3 app/install.py` (Linux: a freedesktop entry and its icon in `~/.local/share`) or `py -3 app\install.py` (Windows: a Start menu shortcut running pythonw, no console window); `--check` says whether it is there, `app/uninstall.py` takes it out (the operator key stays). The install then opens the console on its onboarding window when it has no account (or, without a display, asks the account's root fingerprint for this computer's daemon; `--account FP`, `--skip-account`). Launching the console opens its window in front and starts the computer's daemon; a second launch only brings the running window to the front.
- **Hidden sessions**: what the daemon starts runs without any window; *Output* beside each started session shows its live output, a line to write into it, and Stop.
- **Butlers and new sessions from the explorer**: on each computer its butler is the first entry, highlighted (or *Start a butler…*, which asks its agent and model, then Cancel or Launch); the Butler tab lists every computer's butler and inventory (declared with its box) with a Refresh each; *New session…* above the list (a computer, project or box selected) opens computer, project or folder, agent, model, title and first task, prefilled from Settings (*Butler and new sessions*: the butler's agent and model, the sessions' defaults) and the selection.
- **A box's menu** (⋮ on a box of this computer): *Purge its history* (what no longer waits among its messages, from its log, attached files and the console's copy, as the memory view's purge for this box alone), *Empty what waits* (purged unhandled, senders told: `backlog purge`), *Close the session* (an open session box: `sessions --close`), *Delete the project box* or *Delete the closed box* (`sessions --remove`: nothing waiting is lost). The handling (execute, ask, ignore) stays below when the box has one.
- **Held messages**: a `queued` message (its sender keeps it, the service refuses it because the recipient does not list the sender yet, typically while no client of the recipient's computer has run since the sender's box was introduced to it) is *held* once it has waited 5 minutes, whichever computer sent it: the console sees it in its own boxes' logs, and in the collectors' `refused` events for the others (once per message every 10 min; one not refused for 30 min is marked as no longer retried, its sender's computer may be off too). Held messages are the console's loudest signal after the questions: a red button in the app bar, a red panel above the message list (per recipient: how many, since when, from whom; hidden until a new one if asked), a red *Held messages* folder at the top of the explorer and a red count on the recipient's machine, project and box, a red row and a red note in the message, and one notification (in the tab, or a persistent system notification with the tray's red dot and a menu entry when no tab notifies), shown again only for a new held message. `/api/pending` gives their count; the window opens on them with `#view=held`. They leave by themselves when the recipient accepts them (they turn `unread`).
- The memory frame (bottom of the explorer) and its view: `GET /api/usage[?fresh=1]` (token required; cached a minute) gives each service's `/v1/usage` where the console is an operator, and the sizes on this computer (console folder: `archive.sqlite`, `attachments/`, the window's data; the boxes' folder). The actions `purge_archive` (a real purge of this computer: every message of the list that no longer waits in a box goes from the boxes' `log.jsonl` (rewritten under each profile's lock; a closed box's log keeps only what still waits), their `attachments/<id>/` folders and the console's copy; kept: `queued`, `unread`, `taken`, `sent` by a box still open, and what an open box sent, received or saw within the kept delay, `purge_keep_s` in `state.json`, 24 h by default, set in Settings with the action `purge_keep`; a marker per purged message in `archive.sqlite` (table `purged`, kept for the collectors' retention and the list's horizon) hides what a collector still holds of it, then `VACUUM`) and `empty_boxes` (`/v1/usage` `empty` on each such service: every box deleted, the operators' own excepted) go through `POST /api/action`.
- Each conversation (the messages a box has sent and received) is kept in `archive.sqlite`, until it expires (by default the longest retention of the collectors read, otherwise `MMBOX_CONSOLE_KEEP_DAYS`, 7), or with no limit while it is pinned.
- Attached files: the console shows those of each box's log from `<profile>/attachments/` (written by the client). Those of an unread message, read in a waiting box, are checked and kept in its own `attachments/<sha256>`. `GET /api/attachment?id=<message id>&i=<index>[&dl=1]` (token required) serves a file only from these folders: inline for a raster image whose bytes match its type, any other file as a download (`application/octet-stream`, `Content-Disposition: attachment`), always with `nosniff` and a `sandbox` policy. A file that is not on this computer answers 404 `not on this computer`.
- The questions received and their answers, and the decisions taken on messages a box asked its user about (Accept or Decline in the message), are kept in `questions.json` (14 days), the imported sound in `sounds/custom.mp3`, the notification settings in `state.json`.
- The window of its own needs pywebview (Debian: `python3-webview`, which brings WebKitGTK 4.1; elsewhere `pip install pywebview`). It shows the page of the URL, with its token; the page's settings (local storage) are kept by WebKit in `~/.local/share/mmbox-console/`, its cookies in `<console home>/webview/`. Attached files are saved through a save dialog, links to other sites open in the browser. Without pywebview or a graphical session the console falls back to the browser.
- On Linux, the notification-area icon and the persistent notification need PyGObject, libnotify and Dbusmenu (Debian: `python3-gi gir1.2-notify-0.7 gir1.2-dbusmenu-glib-0.4`). The icon is a StatusNotifierItem of its own: a click opens the console, or folds its window back into the notification area when it is on screen, the right button shows its menu (open the console, open the local site in the browser, answer the questions, hide in the notification area, quit), the middle button opens the questions when some wait. Where no StatusNotifierWatcher runs, or Dbusmenu is missing, it goes through AyatanaAppIndicator3 (`gir1.2-ayatanaappindicator3-0.1`), whose click shows the menu. Without them, the console works without an icon, and its window then quits when closed. The sound is played by the tab, otherwise by `ffplay`, `pw-play` or `paplay`.
- The ten sounds offered are generated by [tools/make_sounds.py](tools/make_sounds.py), in the public domain ([static/sounds/README.md](static/sounds/README.md)).
